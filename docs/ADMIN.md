# Админка — текстовая версия инструкции

Полная иллюстрированная версия: [`docs/admin-guide-ru.pdf`](./admin-guide-ru.pdf).
Этот файл — то же самое текстом, чтобы можно было искать по словам.

---

## 1. Как всё устроено

```
Вы → админка (/admin) → Supabase (данные + файлы) → сайт на Vercel → посетитель
```

| Название | Что это для вас |
|---|---|
| **Vercel** | Здесь живёт сайт. Заходите один раз — вписать два ключа. |
| **Supabase** | База: проекты, тексты, загруженные файлы. Настроить и забыть. |
| **Админка** | Страница `/admin` на вашем сайте. Здесь вы работаете. |

Сайт не ломается, если база недоступна: он показывает исходные двенадцать проектов
из кода. Пустой страницы посетитель не увидит никогда.

**Через админку меняется:** фон первого экрана, фото в «Обо мне», картинка для соцсетей,
миниатюры и превью проектов, сами проекты (все поля, три языка), галерея внутри проекта,
порядок, скрытие, удаление, иконки-ссылки в подвале сайта (Behance, LinkedIn, WhatsApp,
телефон и что угодно ещё — раздел «Контакты»).

**Не меняется:** заголовок героя, тексты «Обо мне», компетенции, опыт — они в `src/i18n.js`.
Сам email и номер телефона в кнопке «Оставить заявку» и в текстах юридических страниц
тоже остаются в коде — «Контакты» управляют только иконками-ссылками в подвале.

## 2. Разовая настройка: база

1. **Проект в Supabase.** [supabase.com](https://supabase.com) → New project.
   Регион `Central EU (Frankfurt)`. Пароль базы сохранить сразу — второй раз не покажут.
2. **Таблицы.** SQL Editor → New query → вставить весь `supabase/schema.sql` → Run.
   Ожидаемый ответ: `Success. No rows returned`.
3. **Проекты.** New query → весь `supabase/seed.sql` → Run. Повторный запуск дубликатов
   не создаёт, только обновляет тексты.
4. **Логин.** Authentication → Users → Add user → Create new user.
   Обязательно включить **Auto Confirm User**.
5. **Права.** SQL Editor:
   ```sql
   select public.grant_admin('вашапочта@example.com');
   ```
   Ответ: `Готово: … теперь администратор.`

**Проверка:** пять таблиц в Table Editor (`projects`, `project_media`, `site_media`,
`site_settings`, `admin_users`), двенадцать строк в `projects`, ваша почта в Users с датой
подтверждения, одна строка в `admin_users`.

> Если база уже была настроена раньше (до появления `site_settings` и раздела
> «Настройки» в админке) — просто откройте `supabase/schema.sql` заново и выполните
> его целиком в SQL Editor. Скрипт идемпотентный: существующие таблицы и данные не
> трогает, только добавляет то, чего не хватает.

### Чтобы база не «засыпала»

На бесплатном тарифе Supabase ставит проект на паузу, если к нему **семь дней подряд**
не было ни одного запроса. Сайт тогда перестаёт грузить данные, пока кто-нибудь вручную
не нажмёт «Restore» в панели Supabase.

В репозитории есть готовый файл `.github/workflows/keep-alive.yml` — он раз в три дня
дёргает базу лёгким запросом, и до недельного лимита дело не доходит. Чтобы он заработал,
один раз добавьте на GitHub два секрета с теми же значениями, что и в `.env.local`:

1. Репозиторий на GitHub → **Settings → Secrets and variables → Actions → New repository secret**.
2. Добавить `SUPABASE_URL` = ваш Project URL.
3. Добавить `SUPABASE_ANON_KEY` = ваш anon public ключ.

Дальше всё автоматически — вкладка **Actions** в репозитории покажет, что `Keep Supabase
awake` отрабатывает по расписанию. Если нужно проверить прямо сейчас — там же можно
нажать «Run workflow» и запустить вручную.

## 3. Разовая настройка: сайт

Supabase → Project Settings → API. Нужны **Project URL** и **anon public**.

> Ключ `service_role` лежит рядом и даёт полный доступ в обход всех ограничений.
> Его нельзя вставлять в настройки сайта, в переписку и на скриншоты.

Vercel → Settings → Environment Variables:

```
VITE_SUPABASE_URL      = https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY = eyJhbGci...
```

Отметить Production + Preview + Development, сохранить, затем
**Deployments → ⋯ → Redeploy**. Без пересборки старый сайт ключей не увидит.

Необязательно: `VITE_SITE_URL` с адресом сайта. Нужна только для карты сайта,
которую читают поисковики. Пока переменной нет, карта не создаётся — и это нормально:
лучше без карты, чем карта с чужим адресом. На продакшн-сборке Vercel подставляет
адрес сам, так что вписывать это стоит только когда появится собственный домен.

## 3а. Разовая настройка: письма с формы заявки

Форма «Оставить заявку» на сайте отправляет письмо напрямую на
cookiekiller.design@gmail.com через [Web3Forms](https://web3forms.com) —
сервис, который принимает данные формы прямо из браузера и рассылает их по
почте, без своего бэкенда. Чтобы это заработало, нужен один ключ:

1. [web3forms.com](https://web3forms.com) → регистрация письмом
   **cookiekiller.design@gmail.com** (бесплатного тарифа хватает с большим
   запасом). Access Key придёт на почту сразу же и всегда доступен в личном
   кабинете на сайте.
2. Vercel → Settings → Environment Variables → добавить
   `VITE_WEB3FORMS_ACCESS_KEY` с этим значением, отметить
   Production + Preview + Development.
3. **Deployments → ⋯ → Redeploy.**

Этот ключ — не секрет в привычном смысле: Web3Forms специально сделан так,
что ключ виден в браузере (иначе форма без бэкенда не смогла бы его
использовать). От чужого использования и спама защищает сам сервис — в
личном кабинете можно ограничить приём заявок только с домена сайта.

Пока `VITE_WEB3FORMS_ACCESS_KEY` не задан, форма на сайте покажет
посетителю сообщение об ошибке вместо тихого «отправлено» — заявки без
настроенного ключа никуда не теряются незаметно.

## 4. Вход

`https://ваш-сайт/admin`

| Что видно | Что делать |
|---|---|
| «Осталось подключить базу» | Ключей нет или не было Redeploy → раздел 3 |
| «Неверная почта или пароль» | Сбросить: Supabase → Authentication → Users → ⋯ → Reset password |
| «Доступ закрыт» | Выполнить `grant_admin` — готовая строка показана прямо на экране |
| «Почта не подтверждена» | Не была включена Auto Confirm User при создании пользователя |

Ссылок на админку на сайте нет, для поисковиков она закрыта (`robots.txt` + `X-Robots-Tag`).

## 5. Фото на главной

Раздел **Главная страница**, пять слотов:

| Слот | Что это | Размер |
|---|---|---|
| Фон первого экрана | За большим заголовком. Фото, гифка или видео. Прозрачность держать на 30–40% | от 1920×1080 |
| Фото «Обо мне» | Полоса между текстом и цифрами. Поле «Описание» становится подписью | ≈2400×1000 |
| Картинка для соцсетей | Превью ссылки в Telegram/WhatsApp/LinkedIn/Instagram. Только изображение | строго 1200×630 |
| Фото «Приюты и ветеринары» | Левая половина первой карточки в блоке Side Quests | вертикальный/квадратный, от 1200×1200 |
| Фото «Метал-группы и лейблы» | Правая половина второй карточки в блоке Side Quests | вертикальный/квадратный, от 1200×1200 |

Загрузка — перетащить файл в рамку. Описание сохраняется само при уходе курсора из поля.

**Картинка для соцсетей** подставляется в превью не мгновенно — на стороне Vercel стоит
`middleware.js`, который на каждый запрос страницы подставляет актуальную картинку из базы прямо
в HTML (сайт — SPA, а боты Telegram/WhatsApp/Instagram/LinkedIn JavaScript не выполняют, поэтому
без этого файла они всегда видели бы одну и ту же картинку из сборки, что бы ни было загружено
здесь). Изменения долетают за ~1 минуту (кеш на edge), но у самих мессенджеров есть свой кеш
превью ссылки — если ссылку уже пересылали раньше, старая картинка может показываться ещё
какое-то время, пока их кеш не обновится сам. Если переменные `VITE_SUPABASE_URL` /
`VITE_SUPABASE_ANON_KEY` не заданы в Vercel, middleware просто ничего не трогает — показывается
дефолтная картинка из сборки, сайт не ломается.

**Убрать файл** — для первых трёх слотов блок исчезает со страницы целиком, пустой рамки не остаётся.
Для двух слотов Side Quests блок остаётся всегда (текст и кнопка никуда не деваются) — просто вместо
фото рисуется сгенерированный узор в цвет карточки, так и было задумано, пока фото не загружено.
**Снять галочку «Показывать на сайте»** — блок скрыт, файл сохранён.

Миниатюры проектов задаются не здесь, а в **Проекты → проект → Обложки**.

### Настройки сайта

Раздел **Настройки** — общие переключатели, не привязанные к конкретной странице.

| Переключатель | Что делает |
|---|---|
| Переключатель языка (RU / RO / EN) | Кнопки языка в шапке сайта. Выключен по умолчанию — сайт всегда на английском. Включите, если нужны русская и румынская версии |

Изменение видно на сайте сразу, кэш сбрасывается автоматически.

## 5а. Контакты (иконки-ссылки в подвале)

Раздел **Контакты** — карточки-ссылки, которые показываются в подвале на каждой странице
сайта и в меню на телефоне. Есть из коробки: Behance, LinkedIn, WhatsApp, телефон.
Telegram и TikTok заведены пустыми — карточка не показывается на сайте, пока в ней нет
адреса.

Для каждой ссылки:

| Поле | Что вписать |
|---|---|
| Иконка | Выпадающий список — Behance, LinkedIn, WhatsApp, Telegram, TikTok, телефон, email и ещё несколько; «Другое» — нейтральная иконка-ссылка для всего остального |
| Подпись | Видимый текст ссылки, напр. «WhatsApp» или прямо номер телефона |
| Куда ведёт | Обычная ссылка (`https://…`), номер (`tel:+373…`) или почта (`mailto:…`) |

**Порядок** — стрелками вверх/вниз или перетаскиванием, как у сертификатов. Кнопка
**Добавить** внизу заводит новую пустую карточку — иконку и адрес допишите сразу после.
**Удалить** — без подтверждения не восстанавливается.

> Пока в базе ещё нет таблицы `social_links` (сайт был настроен до появления этого
> раздела) — выполните `supabase/migrate-social-links.sql` в Supabase → SQL Editor один
> раз, как описано в разделе 8б для похожей миграции.

## 6. Новый проект

**Проекты → Новый проект.**

### Основное

| Поле | Что вписать |
|---|---|
| Название | Как в жизни: `Victoriabank` |
| Адрес страницы | Составляется сам. Латиница и дефисы. Даёт ссылку `/project/victoriabank` |
| Статус | Работает / В разработке / Кейс — цветная плашка у названия |
| Платформа | Веб, iOS, Android, мобильное, печать |
| Категория | По ней работают фильтры на странице портфолио |
| Год | Четыре цифры |
| Фирменный цвет | Акцент. Из него рисуется узор-заглушка, если обложки нет |
| Ссылка наружу | Behance, живой сайт, App Store. Можно пусто |

> Адрес у опубликованного проекта лучше не менять — старые ссылки перестанут работать
> и в соцсетях, и в поиске.

### Тексты

Вкладки **Русский / Română / English**, каждый язык отдельно.

- **Название на этом языке** — только если правда переводится. Бренды оставлять пустыми.
- **Подзаголовок** — «Банковская платформа · Продуктовый дизайн».
- **Описание кейса** — 2–4 предложения. Этот же текст идёт в описание для поисковиков.

### Обложки

- **Квадрат в списке работ** — от 400×400.
- **Превью при наведении** — 4:3, от 1600×1200. Эта же картинка растягивается на весь экран
  в блоке «Следующий проект» на странице кейса — чем крупнее файл, тем чётче там будет.

Обе необязательны: без них рисуется узор в фирменном цвете.

### Что использовали

Чекбоксы. Список берётся из блока «Компетенции» на главной.

> Текст и настройки сохраняются **только по кнопке «Сохранить»**. Пока есть несохранённые
> правки, висит жёлтая полоса, а браузер переспросит при закрытии вкладки.
> Загруженные файлы сохраняются сразу.

## 7. Галерея проекта

Появляется после первого сохранения — файлы должны к чему-то привязываться.

Перетащите сразу сколько угодно файлов: загрузятся по очереди, у каждого свой процент.

| Формат | Поведение на сайте |
|---|---|
| JPG / PNG / WEBP | Обычный кадр, по клику — во весь экран |
| GIF | Крутится по кругу, помечен значком «gif» |
| MP4 / WEBM | Без звука, по кругу. Включается сам при появлении на экране, пауза при уходе. В полноэкранном режиме — обычные кнопки |

**Порядок** — перетаскиванием или стрелками `‹` `›` (работают и на телефоне). Сохраняется сам.

**Подписи** — поле под карточкой. Если подписать **каждый** кадр, под галереей появится
кликабельный список названий, как в кейсе «Логотипы для бизнеса».

## 8. Порядок, скрытие, удаление

- **Порядок проектов** — тянуть за шесть точек или стрелки вверх/вниз. Порядок в списке =
  порядок на сайте.
- **Скрыть** — иконка глаза. Проект исчезает с сайта, данные и файлы остаются.
- **Удалить** — красная корзина. Панель покажет, сколько файлов удалится, и переспросит.
  **Отменить нельзя.** Сомневаетесь — скройте глазом.

### Правки не видно на сайте

Сайт кэширует контент на 10 минут.

1. **Обзор → Сбросить кэш сайта.**
2. Обновить вкладку сайта: `Ctrl+F5` (Windows) / `⌘+Shift+R` (Mac).
3. Проверить в инкогнито — там кэша нет.

Для новых посетителей всё видно сразу.

## 8а. Legals (Privacy Policy, Terms, GDPR, Cookie Policy)

Раздел **Legals** в левом меню, под ним четыре страницы: **Privacy Policy** (текст
страницы `/privacy`, свой более подробный редактор с предпросмотром — см. ниже),
**Terms of Use** (`/terms`), **GDPR** (`/gdpr`) и **Cookie Policy** (`/cookie-policy`).
Все четыре — на трёх языках, вкладки Русский / Română / English.

Privacy Policy:

- Пока текст не трогали, в редакторе показан встроенный вариант, и на сайте он же.
- Разметка простая: строка `## Заголовок` начинает новый нумерованный раздел,
  пустая строка — новый абзац, `**жирный**`, `[текст](https://ссылка)`.
  Всё до первого `##` — вступление под названием страницы.
- Справа — предпросмотр, обновляется по мере набора.
- «Вернуть стандартный» подставляет встроенный текст для текущего языка.
  На сайт попадает только после **Сохранить**.
- Дата «Обновлено» на странице ставится сама при сохранении.

Что в тексте должно соответствовать реальности: форма только открывает почту
(ничего не хранится), хостинг Vercel, база Supabase, почта Gmail, аналитики и
cookies нет. Если добавите аналитику или настоящую отправку формы — поправьте
разделы «Что и зачем» и «Кто ещё».

## 8б. Сколько места осталось

На **Обзоре** есть блок «Место в Supabase»: две шкалы — файлы в bucket и база данных.
Занятое место считается по факту; лимит подставляется по тарифу (бесплатный:
1 ГБ файлов и 500 МБ база; Pro: 100 ГБ и 8 ГБ). Если оплатили Pro — включите
переключатель «Тариф Supabase — Pro» в Настройках, иначе шкала будет врать.

Чтобы блок заработал на базе, созданной раньше, один раз выполните
`supabase/migrate-usage.sql` в SQL Editor. Трафик (egress) сюда не попадает —
его видно только в Supabase Dashboard → Usage.

## 8в. Ускорение загрузки сайта (необязательно)

Главная страница раньше собирала контент восемью отдельными запросами к Supabase —
на медленной связи они выстраивались в очередь и заметно тормозили первую отрисовку.
Теперь есть функция `get_site_content()`, которая отдаёт всё то же самое одним
запросом.

Сайт работает и без неё — если функции ещё нет в базе, он сам, незаметно для
посетителя, переключается на старый способ. Но чтобы получить ускорение, один раз
выполните `supabase/migrate-combined-content.sql` в Supabase → SQL Editor, как
описано в разделе 8б для похожей миграции. Безопасно выполнять повторно.

## 9. Какие файлы готовить

| Куда | Размер | Формат и вес |
|---|---|---|
| Фон первого экрана | от 1920×1080 | JPG/WEBP до 1 МБ или MP4 до 15 МБ |
| Фото «Обо мне» | ≈2400×1000 | JPG/WEBP до 800 КБ |
| Картинка для соцсетей | строго 1200×630 | JPG/PNG до 500 КБ |
| Квадрат в списке работ | от 400×400 | JPG/WEBP до 300 КБ |
| Превью при наведении | от 1600×1200, 4:3 | JPG/WEBP до 700 КБ |
| Кадры галереи | от 1600 по ширине | JPG/WEBP до 800 КБ · GIF до 5 МБ · MP4 до 30 МБ |

Три правила важнее цифр:

1. **WEBP вместо JPG** — тот же кадр весит на 25–35% меньше.
2. **Видео лучше гифки** — 10 секунд в GIF это 8 МБ, в MP4 — 600 КБ и чище.
3. **Держитесь в пределах 1 МБ на кадр.** Технический предел 200 МБ — это предел,
   а не ориентир.

Сжать: [squoosh.app](https://squoosh.app) для картинок, [handbrake.fr](https://handbrake.fr)
для видео.

| «Нет прав на это действие» | Выполнить `grant_admin` со своей почтой, обновить страницу |
| «Такой адрес проекта уже занят» | Допишите год: `victoriabank-2025` |
| «Файл весит больше лимита в 200 МБ» | Сжать в HandBrake или выложить на YouTube и дать ссылку наружу |
| «Сессия истекла» | Обновить страницу, войти заново |
| «Нет связи с сервером» | Проверить интернет, затем [status.supabase.com](https://status.supabase.com) |
| Загрузка застряла на 0% | Медленный канал. Через 5 минут — обновить страницу, взять файл поменьше |
| Проект не виден на сайте | Не нажали «Сохранить» / снят глаз / не сброшен кэш |
| Вместо фото цветной узор | Так и задумано без обложки. Если обложка есть — файл не открывается, пересохранить в JPG |
| На сайте старые двенадцать проектов | Сайт не достучался до базы: проверить ключи и Redeploy |

## 11. Чего делать нельзя

- **Показывать кому-либо ключ `service_role`.** Полный доступ в обход всех ограничений.
- **Удалять таблицы в Table Editor.** Удалённая `projects` — это все проекты сразу.
- **Менять адрес у опубликованного проекта.** Ломает все существующие ссылки.
- **Выключать Row Level Security.** Это то правило, из-за которого чужой может читать сайт,
  но не может ничего в нём поменять.

Наоборот полезно:

- Хранить оригиналы файлов у себя — в панели лежат сжатые версии.
- Перед удалением сначала скрыть глазом и подождать неделю.
- Пароль от админки — в менеджере паролей.
- После крупных правок открыть сайт в инкогнито.
- Раз в пару месяцев чистить Supabase → Storage.

## 12. Словарик

| Слово | Что значит |
|---|---|
| Деплой | Сборка и публикация сайта |
| Redeploy | Пересобрать заново, ничего не меняя в коде. Нужен, чтобы подхватить ключи |
| Кэш | Память браузера. Лечится `Ctrl+F5` |
| Slug (адрес страницы) | Кусок ссылки: в `/project/victoriabank` это `victoriabank` |
| RLS | Правила базы: читать — все, менять — только вы |
| Storage | Место в Supabase, где физически лежат файлы |
| anon key | Публичный ключ, только чтение опубликованного. Ему и положено быть в браузере |
| service_role key | Секретный ключ с полным доступом. Не для вас и не для сайта |
| SQL Editor | Поле в Supabase для готовых команд. Свои придумывать не нужно |
| i18n | Всё, что связано с тремя языками сайта |
